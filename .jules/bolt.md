## 2024-05-18 - [DataTable Drawer Re-rendering Optimization]
**Learning:** The `TableCellViewer` in `apps/app/app/components/data-table.tsx` rendered the heavy `ChartContainer` and `AreaChart` components within the `DrawerContent` immediately, regardless of whether the drawer was open. Because this is repeated for every row in the `DataTable`, it caused a large performance and memory footprint overhead when rendering many rows.
**Action:** Used `useState` to track a `hasOpened` state, initially false. Set this to true in the `Drawer`'s `onOpenChange` when `open` is true. Then conditionally rendered the `DrawerContent`'s children only if `hasOpened` is true. This defers the rendering of charts and inputs until the user actually opens the drawer, while preserving the content if they close and reopen it.
